# Migration v3.0.x → v3.1.0

## Narrative

```
WAVES 3.1 — waves_files + collaboration substrate

The artifacts directory is renamed ai_files/ → waves_files/ (brand-prefixed,
grep-unique — 'ai_files' could be any AI tool's folder; 'waves_files' is
unambiguously this framework's). The kernel resolves BOTH names (waves_files
preferred, ai_files fallback), so this migration is a convenience rename, not
a breaking change — but new projects are born as waves_files/ and the
fallback eventually retires.

The same migration wires the collaboration substrate: the waves merge driver
(two people editing the same artifact on different branches merge per-field —
git never writes <<<<<<< into an artifact) and the pre-commit backstop
(malformed or newly-invalid artifacts cannot be committed from ANY editing
surface).
```

## Safety flags (declared in the frontmatter)

- `requires_clean_git: true` — `git status --porcelain` must be empty before
  applying. Git is the only safety net for a directory move; ABORT if dirty.
- `destructive: true` — show the plan (the exact `git mv` and wiring commands
  below, with resolved paths) and ask for explicit confirmation before
  applying. With `--dry-run`, print the plan and STOP.

## Steps

1. **Pre-flight.** Verify this is a git repository with a clean tree
   (`git status --porcelain` empty). If not → ABORT with the reason; change
   NOTHING. If `waves_files/` already exists → fingerprint should have
   skipped; re-verify and stop.

2. **Rename the artifacts directory (history-preserving).**
   ```
   git mv ai_files waves_files
   ```
   For a multi-project repo (capability #9), also rename each child:
   `git mv projects/<name>/ai_files projects/<name>/waves_files` for every
   `projects/*/ai_files` that exists.

   **Content is NOT rewritten.** Historical artifacts (old logbooks,
   roadmaps, resolutions, CHANGELOG entries) that mention `ai_files` in their
   prose keep saying `ai_files` — they are immutable snapshots of their
   moment. Only the directory moves.

3. **Wire the merge driver** (idempotent):
   ```
   bash ${CLAUDE_PLUGIN_ROOT}/kernel/bin/waves-merge-setup --repo .
   ```
   This writes `[merge "waves"]` to `.git/config` (local, every clone) and
   appends the routing lines to `.gitattributes` (committed, travels).

4. **Install the pre-commit backstop** (idempotent; preserves and chains any
   pre-existing pre-commit hook):
   ```
   bash ${CLAUDE_PLUGIN_ROOT}/kernel/bin/waves-pre-commit-install \
     --schemas ${CLAUDE_PLUGIN_ROOT}/skills/waves-protocol/references --repo .
   ```

4.5. **Rewrite dead path pointers `ai_files/…` → `waves_files/…`** (the rename
   in Step 2 moved the directory; literal path strings INSIDE artifact content
   still point at the now-empty `ai_files/` location — and the kernel's dual
   resolution only picks the scope ROOT, it does NOT rewrite literal paths
   embedded in content. An agent reading such a pointer hits a missing file and
   falls back to grep). This is a content edit, but it does NOT violate
   snapshot immutability: a snapshot's intent is to point at the OBJECT, and the
   object merely moved — keeping the pointer valid preserves the record; a dead
   pointer degrades it.

   **The discriminator is purely syntactic — no judgment, no LLM:**
   ```
   # Pointer  = ai_files/ followed by a path char     → REWRITE (was RELOCATED)
   # Concept  = ai_files/ followed by space/punct       → PRESERVE (the directory
   #            as a topic of prose, e.g. "rename ai_files/ -> .waves/")
   # Legacy-DELETED = ai_files/schemas… and ai_files/.waves-version → PRESERVE.
   #            These were REMOVED by the v2->v3 migration (schemas now ship in
   #            the plugin; the marker was retired), NOT relocated — there is no
   #            waves_files/schemas/ in a migrated consumer repo, so rewriting
   #            them would invent a worse dead path AND falsify any migration
   #            narrative that says "ai_files/schemas/ is removed".
   #            (.waves-version is already safe: the '.' is not a path char.)
   #
   # Apply over artifact files only, EXCLUDING test fixtures (sandboxes
   # deliberately model an ai_files/ layout; rewriting them breaks the tests).
   # The (?!schemas) lookahead skips the deleted-legacy schemas dir; the per-token
   # split rewrites only the segment BEFORE the first sandbox/ (so a reference
   # INTO a fixture path like .../sandbox/x/ai_files/ keeps its internal ai_files):
   find waves_files projects/*/waves_files -type f \( -name '*.json' -o -name '*.md' \) 2>/dev/null \
     | grep -v '/sandbox/' | grep -v '/ai_files/' \
     | while IFS= read -r f; do
         grep -qE 'ai_files/[A-Za-z0-9_]' "$f" || continue
         perl -i -pe 's{(\S+)}{
           my $t=$1;
           my $sub = sub { my $s=shift; $s =~ s#ai_files/(?!schemas)([A-Za-z0-9_])#waves_files/$1#g; $s };
           if ($t =~ m{sandbox/}) { my ($pre,$post)=($t =~ m{^(.*?sandbox/)(.*)$}s); $t=$sub->($pre).$post; }
           else { $t=$sub->($t); }
           $t
         }ge' "$f"
       done
   ```
   **Dry-run:** in `--dry-run`, do NOT run `sed` — instead list the files and the
   pointer count per file (`grep -coE 'ai_files/[A-Za-z0-9_]'`) and STOP.
   **Verify after applying:** `grep -rE 'ai_files/[A-Za-z0-9_]' waves_files | grep -v '/sandbox/' | grep -v '/ai_files/'`
   must be empty (only the preserved concept-mentions and the deleted marker
   remain). NOTE: this fixes the `ai_files→waves_files` prefix only; it does NOT
   touch the separate flat→directory-per-logbook relocation (that is the v2→v3
   migration's concern).

5. **Commit the migration** with EXPLICIT paths (never `git add -A` — a blanket
   add would sweep in unrelated work-in-progress that happens to be staged):
   ```
   git add waves_files .gitattributes
   # multi-project: also `git add projects/*/waves_files`
   git commit -m "waves: migrate to v3.1 (waves_files rename + merge driver + pre-commit)"
   ```
   The migration commit must contain ONLY the rename + wiring. If
   `git status --porcelain` shows anything else still uncommitted after the
   explicit add (collateral from before the migration), that is fine — it stays
   out of this commit; but if the working tree was supposed to be clean
   (Step 1 required it) and isn't, STOP and ask for a separate commit first.
   Note: the pre-commit backstop is already active for this commit — expect
   warnings (not blocks) if legacy artifacts carry pre-existing schema errors.

6. **Verify.**
   - `test -d waves_files && ! test -d ai_files` (single-project) — both
     conditions true.
   - `git config merge.waves.driver` prints the kernel driver line.
   - `git rev-parse --git-path hooks` contains an executable `pre-commit`
     mentioning "waves-pre-commit backstop".
